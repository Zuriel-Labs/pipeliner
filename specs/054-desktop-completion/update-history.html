Issue #54 — protected update history

D-24, S-14, R-43, NFR-10/NFR-12, F-08 and T-18 require authenticated availability, retained release identity and deliberate installation. This increment supplies host-owned availability history. It grants no installation authority and does not configure a production publisher.

Existing architecture and plan

Reuse the private SQLite file checks, installed Node SQLite, vault AES-GCM and authenticated record codec. Add a dedicated update payload purpose; do not mix update history with deletable conversation/log retention or restorable PM configuration. Identify each stream by trusted publisher ID, exact origin/path, public-key fingerprint, channel and compatible host. Keep sequence, signed envelope and attempt/check times inside the authenticated payload. Bound the database and stream count.

  1. Write one regression using synthetic OS wrapping, real vault encryption, ephemeral Ed25519 signatures and an external temporary database. Verify persistence, rate limiting, identical-envelope refresh, replay/substitution denial, stale completion, corrupt/closed protection and exact fixture cleanup.
  2. Implement host-only read, begin, complete, fail and close operations. Persist an attempt before network dispatch. Automatic begin returns no work before 24 hours; a deliberate manual check may retry. Only one local attempt is live. A completion must match the unchanged durable attempt and advance the authenticated sequence, or refresh the exact previously verified signed envelope. An equal sequence with changed metadata or signature refuses.
  3. Verify cached signatures against the recorded successful check, then recheck current time and installed version before exposing availability. Expiry hides availability while retaining the sequence. Invalid/backwards time, unknown schema, modified encrypted records or lost protection refuse without resetting history.
  4. Run update-history, manifest, reader, vault and record regressions through an admitted external launcher, then the complete configured npm run check. Integrate the store with the host reader and PM chat/Settings in the next increment, with policy/source changes and shutdown cancelling an in-flight result.

Acceptance and verification

A restart preserves the highest verified sequence and the daily attempt limit. A failed or interrupted check preserves the last known verified release and sequence. An identical still-fresh signed envelope may refresh availability; lower sequences and changed envelopes at the same sequence never replace it. A newer valid signed envelope advances the sequence atomically. A stale completion never overwrites a newer attempt. Protected records cannot be decoded as another purpose or source stream. Tests must inspect the database for absence of synthetic private metadata and remove only their own temporary fixtures.

Focused command: node --test desktop/updates/history.test.mjs desktop/updates/manifest.test.mjs desktop/updates/source.test.mjs desktop/connections/vault.test.mjs desktop/privacy/records.test.mjs. The current storage admission failure blocks execution; writing a regression is not a Red or Green result. No unchanged blocked retry is planned.

Non-goals and risks

No renderer-supplied URL/key, worker access, network dispatch, feed publication, automatic download/install/restart, native binary trust, idle installation, migration, rollback or uninstall is implemented here. No new dependency or generic persistence framework is needed. AES-GCM authenticates the stored history; it does not establish hardware-backed monotonic state or resistance to an OS-authorized rollback of the entire installation vault and database. Publisher revocation and catalog changes remain host authority. Missing signing/notarization and live publisher evidence remain pending.

Implementation status

The prewritten regression and host-only store are implemented. Tests have not run because the managed storage admission route remains unqualified. Only source whitespace checks have passed; no persistence, cryptographic regression, native Keychain or complete quality result is claimed. No app control or packaged runtime input is activated by this increment.
