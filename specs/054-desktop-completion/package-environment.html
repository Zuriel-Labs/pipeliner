Issue #54 — local package environment

The review builder already stages exact committed runtime inputs, pins downloaded artifacts, disables package lifecycle scripts, verifies archive integrity and checks nested signatures. It currently changes HOME for most child commands, restores HOME for signing only, and requires an arbitrary four GiB of free capacity. The next local build must preserve the user's real home while directing disposable compiler files explicitly into its existing private build directory.

Scope and plan

Continue D-23/D-24, R-24/R-43, NFR-04/NFR-10/NFR-12 and F-08/T-08/T-18. Use the same explicit child environment for ordinary and signing commands, with the real home, private temporary directory and private Clang module cache. Keep explicit empty npm configuration files and its private cache. Disable curl's implicit configuration-file loading before supplying the existing exact HTTPS download arguments. Remove the arbitrary builder capacity floor; actual write/download errors remain failures with owned-build cleanup.

Acceptance

  1. Review every child command for home-dependent configuration or cache behavior. No credentials are copied into build output.
  2. Run the complete configured npm run check on the clean committed source and record any unresolved failures separately.
  3. Run node scripts/desktop-package.mjs on the compatible Mac. Verify exact source/tree, archive inputs, downloaded digests, nested signatures, packaged startup refusals, DMG verification and retained artifact digest.
  4. Inspect actual output paths and remove only the builder's owned intermediate resources. Retain the identified review artifact and evidence for PM testing or replacement.

Risks and non-goals

A successful build does not prove installer, rollback, provider journeys, Human acceptance, Developer ID notarization or other operating systems. The intermittent recovery-test metadata finding remains unresolved until attributed and verified; an instrumented passing run is not a correction. Native OS-service scratch is a separate producer qualification question. No runtime authority, trust requirement, security assessment, test assertion or installed tool changes are part of this builder increment.
