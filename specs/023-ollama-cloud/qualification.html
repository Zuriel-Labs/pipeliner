Selected Cloud model loop qualified through installed Ollama

Bounded synthetic evidence on the current Mac. Product delivery has remaining requirements.

Decision and PM direction

The PM authorizes the installed Ollama service's cloud models for now and requests inexpensive models such as DeepSeek 4.1 Flash. The explicit temporary route successfully runs a streamed tool request, one validated synthetic effect, result follow-up, checkpoint resume, wrong-target denial and cancellation after response bytes. This qualifies the selected model loop through that route.

The original direct Cloud API-key request returned HTTP 401 on 29 September. Its cause remains unknown. The temporary relay result does not prove production R-22 authentication. Final Draft 1.0 retains direct Cloud API keys; product delivery must reverify that path. No key scope, key insufficiency or global provider compatibility is inferred.

The official DeepSeek model page specifies deepseek-v4.1-flash:cloud for the installed service. The Cloud guide distinguishes installed-service sign-in from direct API keys. The revision and acceptance change are recorded in the Issue and pre-code specification.

Agent review

Resolved findings: local mode must be explicit and must drop the environment key; resumed state must bind model and route as well as target and policy; cancellation must invalidate a response even if consumption finishes; returned model changes and truncated responses must fail closed. The existing parser, broker and checkpoint are reused. No new SDK or third-party dependency is added.

Remaining limitations: production protected key storage, renderer/provider integration, complete pipeline tools/skills/MCP coverage, hard spend limits, broad model matrix, vision, worker VM integration, Windows/Linux and whole-app PM Testing are unverified. The observed token fields support visibility; they do not establish monetary charges or a hard-budget guarantee. No general Fully Autonomous eligibility is claimed.
