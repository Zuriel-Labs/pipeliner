Execution contract

  1. Inspect the selected registered repository, complete Issue/Project catalog, Ready, dependencies, current active slot and selected Dev. Verify connection/resource access and actual worker capability. Retain unsupported capability explanations. A start request never adds Ready.
  2. Capture policy, Development graph, source commit/tree, selected Dev/model, starter inventory and deadlines. Reserve using the existing runtime before a worker can start. Record the active transition before dispatch and read it back. Lost replies remain uncertain.
  3. Read only immutable committed Git objects from the verified repository into a bounded regular-file snapshot. Never copy local modifications, untracked files, credentials, Git config or host mounts. Verify source against the selected remote before publication. Existing local changes remain untouched.
  4. Seed the existing app-owned rootless worker through bounded stdin. Tool requests execute in that container with its no-network/read-only-root/no-host-mount restrictions. Source write/read/command/output operations validate paths, payloads, identity, current grants and epoch. Export accepts only bounded regular owned files; symlink, hardlink, protected-path and oversized results fail.
  5. Persist each step visit before work, each provider request before sending, and each tool intent before dispatch. A crashed in-flight action requires reconciliation or an explicit restart from verified source; it is not blindly replayed. Persist complete transcript and usage without resetting counters. Enforce captured turns, visits, retries, deadlines and available hard metrics.
  6. Agent steps return typed summaries/documents and references to verified evidence. Require written research/specification/design before source mutation and review evidence before PR preparation. Human documents are dark HTML. Their text never supplies policy, Ready or control authority.
  7. Check steps run the repository's existing reviewed quality commands inside the qualified environment. Record exit code, actual output digest, runtime and exact tree. No model-provided pass flag. If the environment cannot run required tools or dependency/network setup, block with the missing capability.
  8. Candidate source is exported and hashed; checks/review must match that tree. Broker writes only the app-owned branch and linked PR in the selected repository, preserving source/base/head identity. Persist and reconcile every remote effect. Do not invoke an arbitrary host shell, hooks, filters, source scripts or credential helper.
  9. Advance only through the captured route after verified output. Honor finite retry/visit limits and required evidence. At PM QA or PR integration, expose the prepared candidate and next boundary. D-14 does not supply approval, integrate, close the product Issue, or claim Fully Autonomous completion.
  10. Pause/Stop abort provider leases, fence tool dispatch and verify owned worker termination. Resume checks live state, captured source and pending outcomes before a new epoch. Closing the foreground app pauses; background remains off.

Acceptance criteria

  1. One selected qualified Dev and one ready Issue hold the repository claim. Another Issue, stale epoch, revoked grant or unconfigured model cannot act.
  2. Research/specification/design, code, actual tests and review produce persisted typed evidence before linked PR preparation. Missing/invented/old-candidate evidence cannot advance.
  3. Finite graph routing and captured versions survive restart; in-flight uncertainty never causes duplicate mutation. Controls stop/fence provider and worker actions and preserve work.
  4. One small real current-Mac Issue completes the allowed core path to a candidate PR; a denied step has no protected effect. Native test resources are inventoried and removed by exact ownership.
  5. Ordinary chat/Settings/keyboard paths work without technical PM input. Exact capability, source, step, next action and limitations are visible.
  6. All configured repository checks and relevant local/native/security checks pass. Distinguish passed, failed and not run. Current framework tests alone do not prove Desktop behavior.

Risks and recovery

  • Provider success/capability can drift. Refresh at connection/use boundaries; never fall back to another model or provider silently.
  • Git/Project/Issue updates can partially succeed. Record intent before dispatch and retain uncertainty; verify current candidate and owned branch before continuation.
  • Source/tests may mutate or spawn hostile descendants. Keep them inside the qualified worker; inspect cleanup and preserve unrelated resources.
  • Large source/model output may exceed the initial measured envelope. Explicit bounds fail before truncation is treated as evidence. Record the envelope and expand only with needed evidence.
  • Documentation or evidence changes invalidate exact candidate QA. Final full-app Human testing remains pending until an actual complete build and PR exist.
