Ollama Cloud agent loop: partial qualification

Current Mac evidence, with the live inference gate left open.

Decision

The current process’s configured key was rejected by direct Cloud inference. A minimal POST https://ollama.com/api/chat returned HTTP 401 for gemma4:31b, including without tools. The same response was returned with an intentionally invalid key and no key. The synthetic streamed tool loop, resumed answer, usage counters and model capability are therefore not qualified live. No alternate credential or provider session was used.

The PM confirmed Ollama keys have no scopes; the 401 must not be attributed to a missing key scope. The Cloud catalog returned HTTP 200 and 17 API model names, including gemma4:31b. Catalog access does not establish inference permission. The endpoint and model naming follow the official Cloud guide; direct Cloud inference authentication follows the official authentication guide.

Risk and next verification

The probe denies tool dispatch until a complete terminal stream and exact target, nonce and policy epoch are validated. It checkpoints a single synthetic effect with restrictive mode and checks replay on resume. The untested Cloud response shape may differ from the local fixtures. The current process receives a 57-character ASCII key without surrounding whitespace or quotes, and the harness constructs the documented bearer header and fixed endpoint. That establishes request construction, not provider acceptance. The remaining cause could be a mismatch between the key available to this process and the intended account key, or a provider-side rejection; evidence does not distinguish them. Resolve that cause before rerunning node desktop/ollama/qualify.mjs. Do not paste a key into chat or GitHub.

Temporary checkpoint directories are removed by the probe in success and failure paths; this blocked HTTP 401 path created none. No local Ollama daemon or application process was started.
