Smallest correct design

Reuse the original starter pack and capability metadata rather than adopting untracked repository/home skills. The required capabilities remain covered by Forge (coding), Motif (direction/interaction/system), Shape (implementation/mockup translation) and Lens (accessibility/UX/security review). Keep their actual names/source/version/digests inspectable. Enhance concrete output guidance only where the existing prompt is insufficient; any content change creates a new version/digest and does not replace an active run's capture.

Add one application-owned instruction registry with strict immutable package records and content pins. Reuse protected SQLite/storage helpers and policy preview/apply. Repository/global selections use the existing bundled-enabled, selected pinned extensions and disabled references. Source authorization and installation do not grant worker tools. Keep different versions addressable until no captured run needs them; update chooses a new pin for future runs, disable/remove tightens authority immediately. A package store cannot write the policy or call PM control. Removed/unavailable required content blocks before a turn or effect.

Qualified external sources are immutable public GitHub commit/path packages selected deliberately by the PM; discovery/read is separate from install/apply. Exact source, commit, license, content digest, supported content and affected scope appear in the preview. Require host/repository extension.install authority for agent-driven install and the exact captured approved source/package pin. No runtime approval is added to an already authorized Fully Autonomous path. A missing approved source or required capability blocks before execution. Never use an account token to widen public package discovery or accept redirects to a foreign origin.

Initial external packages are bounded instruction/data skills: SKILL.md plus explicitly supported local text references/license. Validate YAML with duplicate keys/errors/warnings handled, bounded UTF-8/size/nesting, no aliases/custom tags/prototype keys and explicit license/version. Reject executable scripts, installation hooks, dependency declarations, symlinks/submodules, traversal, credentials and unsupported resources before installation. Tool hints are visible requirements only; they cannot create permission. Broader execution/transport remains D-21/D-22 qualification. This is a capability limitation, not a claim to support every Agent Skills package.

PM names are globally unique in the installed inventory. Preserve original source name separately from any explicit PM-selected alias. Collision yields available relevant single-word alternatives, never overwrite or automatic rename. Installation effects have a durable intent, verified readback and explicit recovery if interrupted; uncertainty never becomes an automatic repeat. Package content is data escaped in UI/documents and enclosed within host-enforced run instructions.

Design brief

PM task: understand what each skill does and which repository can use it, then add/enable/disable/update/remove without technical setup. Scope and effective selection lead; details progressively expose pins/license/requirements. Reuse existing typography, semantic tokens, 44px labeled controls and readable cards. States: no repository, inherited/default inventory, selected, disabled, discovering, pinned source preview, collision choices, installing, unavailable required content, integrity failure, cleanup/retry and success. Preserve drafts, keyboard focus and reading position; status announcements report meaningful outcomes without focus theft. Narrow/200% zoom, light/dark, high contrast and reduced motion are verified. Human VoiceOver/full-app tasks remain separate.

Risks and non-goals

Untrusted YAML/text/package resources, network redirects, license ambiguity, content substitution, global name races, stale PM proposals, revoked old pins, storage interruption and legacy capture drift are concrete risks. Fail closed with readable recovery and preserve claims/evidence. No copied home skills/sessions/keys, arbitrary archive/script installer, MCP/custom steps, new host execution privileges, framework adoption changes, installer/notarization, whole-app usability/soak or other-OS support claim. No roadmap runtime/package surface. Security/accessibility fundamentals accompany this slice; later milestones are not permission to defer them.
