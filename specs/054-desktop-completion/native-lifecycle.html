Focused specification and smallest design

Add a separately pinned, explicit provider for kernel lifecycle certificates of naturally closed ordinary in-group members. Preserve the existing audited ledger as its own provenance; never insert an unaudited kernel record into that ledger. Keep original detached enrollment, native ownership, complete captured-view equality, full frozen filesystem audits/resume, the single refresh, scanner limits, source/custody binding and watchdog recovery.

A certificate must bind a private observer epoch, exact verified provider source, high-resolution native birth, full audit-token incarnation, owner, parent ancestry, session/group and the relevant loss-checked lifecycle interval. Bind it to the entire captured view and the current admitted producer. Require complete owned-descendant coverage and independently observed native absence. A PID, rounded process-list birth string, timestamp, notification callback or recorded exit alone cannot establish closure. Delayed notification delivery must remain distinct from the kernel's identity capture time.

Reuse the reviewed bounded JSONL/identity codec only after checking its actual semantics against this contract. Maintain separate per-type and global loss checks, frame/aggregate/member limits, schema/version checks and typed refusals. Extract only scoped identity evidence; discard unrelated arguments, environment, file data and raw events from volatile memory. No raw process stream belongs in retained artifacts.

The provider must refuse PID reuse, ambiguous rounded-time matches, changed incarnation or credentials, unknown ancestry, surviving orphans, missing lifecycle coverage, loss/truncation, observer replacement or loss, stale source/custody, partial views and unverified native queries. No automatic retry, limit increase, serial test schedule, skipped test or successful-close inference is permitted.

Primary-source research: Apple's per-type counter and global counter are per-client loss indicators. Preserve the actual supported field/version representation. The current global-counter web page says message version greater than 4, while the installed ESMessage.h:2687 says at least 4; this discrepancy is recorded rather than silently resolved. Installed ESMessageCore.h:111 represents start time as timeval, with microsecond precision. Apple's process documentation distinguishes kernel exec metadata from full executable-page validation; existing image/source custody remains required.

Acceptance, non-goals and risks

Acceptance requires authoritative initial identity plus independent complete closure for the actual naturally closed actors that previously caused quality_group_identity_unverifiable, while every original audit/admission invariant remains true. Focused injected checks, source pins, syntax or framework checks alone do not establish this. Complete configured quality, current app build, native recovery/removal, provider and VM behavior, accessibility, workload/soak and Human PM acceptance remain pending.

Non-goals: weakening original guards; requiring every ordinary child to wait before its first instruction; replacing official pinned helper bytes; changing global tools/configuration or OS permissions; collecting unrelated process data; inventing closed-actor attribution; rerunning the unchanged failed route; or treating observer preparation as product/native qualification. Source, Git, dependencies, credentials and Stable installs remain internal; generated testing/build/log/cache data use admitted external runs. Retained evidence and unrelated resources remain preserved.

Risks include PID reuse and exec incarnation changes, rounded-time ambiguity, event loss or schema drift, missing ancestors, orphan survival, privilege/consent mismatch, root supervisor cleanup failure, control-channel forgery and audit/stream races. Refuse ambiguous state. Instrumentation overhead is not product responsiveness.

Verification commands are the provider's bounded offline certificate regression and exact source-pin/custody checks; the reviewed node scripts/desktop-quality.mjs --probe; and the configured npm run check only after actual integration admission. The native fixture/supervisor commands must be reviewed with their exact pins before execution. No new administrator trial or privileged logger is authorized by a preparation result.
