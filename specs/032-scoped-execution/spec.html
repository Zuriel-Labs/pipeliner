Issue #32: control and clean up scoped execution

Planning baseline: Final Draft 1.0, M-1 / D-09. Dependency: D-08 / Issue #30, integrated tree 3d99f4524412f6ece13ca7514d057b267f33d6eb. This specification precedes implementation. Standing PM authority covers this intermediate slice; final built-app PM Testing remains required.

Outcome and requirement map

Run one restricted worker; prove a real scoped effect through the durable ledger; provide local Status, Pause, Resume and Stop with independently verified termination and owned cleanup. Preserve the repository reservation, Issue, policy version, candidate and workspace. R-08/R-20/R-25 and NFR-09/NFR-11/NFR-19/NFR-20; T-03/T-06/T-15 and S-05/S-08/S-15. M-1 requires one actual allowed effect, denied unauthorized effect, duplicate/stale rejection and recovery without another effect or lost reservation.

Existing evidence and smallest implementation

Reuse Node SQLite, the D-08 runtime, opaque Git workspace identity, host-only policy authority, Electron sender checks and the existing Pipeliner surface tokens. D-02 demonstrated VM/rootless-container restrictions; its resources were removed. Native Mac process isolation was rejected after automation escaped. No new dependency or unrestricted native worker fallback is planned.

Use a private, local owner SQLite file with a held exclusive transaction for the trusted broker lifetime. The operating system releases its lock on process exit; a second broker fails closed. Persist execution resource records in a separate protected SQLite sidecar, rather than changing the immutable policy document or adopter profile. Record ownership before creation, then exact container identity after creation. A new broker must inspect and terminate former execution before it can resume the reserved run with a new epoch.

The trusted Lima driver has one app-owned private instance scope, a pinned Ubuntu arm64 disk, explicit empty mounts, disabled personal SSH keys/agent/X11 and scrubbed host environment. Rootless containers use exact image identity, private PID namespace, network none, dropped capabilities, no new privileges, read-only root, one guest-only workspace mount, CPU/memory/PID bounds and bounded logs. The VM disk provides a finite workspace ceiling. An unverified VM configuration, image, label, container identity or readback makes execution unavailable.

Typed effect boundary

For this vertical slice, a host-selected workspace target permits creation of one bounded UTF-8 file. The worker supplies data only. Validate exact request keys, bound run/epoch/candidate, captured and current capabilities, content size/hash, allowed relative path and precondition before durable intent/dispatch. Use exclusive, no-follow creation in the opaque inspected Git workspace, flush it and independently read/hash the result. Existing files, traversal, links, global paths and worker-origin control requests are rejected. Store only bounded request data needed for exact recovery. No generic host shell, path proxy or remote credential channel is added. General coding patches belong to later orchestration work.

Controls and interaction brief

Use the Pipeliner navy surfaces, mint work, lavender PM authority and amber pending tokens, system typography and existing spacing. Show repository, Issue, run state and a plain explanation above four semantic 44-pixel controls. Color supplements text. Status requires no provider/model call. Normal states are Running, Pause received, Paused, Resume received, Stop received, Stopped, Recovery required and Blocked; empty shows no active run. Unavailable execution provides the concrete blocker without a false success state.

Pointer and keyboard use the same trusted renderer/main-frame/context channel. Status refresh preserves focus. Pause and Stop immediately persist a received state and block new dispatch; completion becomes verified only after exact termination and effect readback. Stop sends a graceful signal for up to 10 seconds, then uses the container runtime to kill only the inspected owned container and descendants. Resume checks live Issue/candidate/policy, resolved effects and stopped prior execution before incrementing the epoch. Closing the final UI with background off invokes Pause and waits for the same safe boundary. No Issue status change, merge, closure, On Hold or reservation release is implied.

Controls remain readable in narrow/wide windows, light/dark themes, high contrast, 200% scaling and reduced motion. Use visible focus, accessible names, textual pending/error states and a polite status region. Full screen-reader and Windows/Linux behavior remain pending until those hosts/tools are exercised.

Risks and recovery

SQLite locking is for local filesystems; network storage is outside qualification. VM startup/image downloads and rootless cgroup enforcement must be measured, not assumed. Temporary qualification layout does not prove packaged installer or reboot delivery. Container CLI failure never proves termination. Creation is persisted before dispatch so uncertain launches can be inspected by unique name and labels. Resource ownership mismatch blocks destructive cleanup. Preserve workspace data during controls; remove it only during explicit owned test teardown. Report cleanup failures. Node SQLite remains experimental in current Node. VM kernel/container vulnerabilities remain a residual security risk; exact provenance and restrictive configuration reduce exposed authority but do not prove immunity.

Implementation clarifications

Retained guest work uses the private guest user's persistent .local/share/pipeliner/workspaces directory, with an external run ownership marker. Guest /tmp does not preserve work through a VM restart and is rejected as a worker workspace. Rootless container image binding uses the actual manifest digest, rather than its config digest or a mutable tag.

Local cancellation may fence a former host session without granting dispatch authority, changing the epoch or contacting a provider. Worker termination and effect reconciliation remain required before verification. Actual observations share the same operation slot as controls. Final foreground closure waits for pending VM stops before inspecting repositories.

The qualification process subscribes to Electron window-all-closed so it can finish cleanup after the native window closes. No background service is enabled. Validation includes actual host crashes during worker execution and between a file effect and ledger confirmation, plus local Stop during an unavailable repository service. Full OS soak, screen-reader testing, actual memory/disk exhaustion and packaged delivery remain pending.
