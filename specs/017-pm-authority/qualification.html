Decision for this Mac

Keep Electron 44.4.5 as the UI shell recommendation from Issue #15. For arbitrary coding commands, use a separately provisioned VM worker with no host filesystem mounts, a rootless container, no network, a read-only root filesystem, no added capabilities, no new privileges, and only a disposable workspace bind mount. Keep the broker on the Mac with fixed, validated operations and no PM apply endpoint reachable from worker input.

This is a feasibility result for macOS 26.5.2 on Apple Silicon. It does not qualify the production worker image, VM lifecycle, provider adapters, Keychain storage, full policy flow, or broad native app installation and UI automation. Those remain later roadmap work. No unrestricted shell or OS prompt bypass is recommended.

Failed, blocked and not-run

  • Failed native configurations: Apple Events reached Finder in both native process probes. The macOS sandbox-exec manual explicitly marks the command deprecated; the signed helper also inherited an effective automation route. These are rejected mechanisms, not selected-candidate passes.
  • Not run: live Keychain item access, provider OAuth/API keys, GitHub App permissions, PM chat/Settings origin authentication, service persistence, arbitrary native application installation/GUI automation, signing/notarization and Windows/Linux hosts. They require later dedicated qualification and must appear unavailable in product capability reporting until then.
  • Limit: A VM/container boundary reduces host reachability but does not prove absence of all kernel or hypervisor vulnerabilities. This test used a fixed local tool image and synthetic data; later work must pin and review production images, patch/update behavior, VM lifecycle, and brokered Mac build/test operations.

Product contract preserved

PM-owned configuration and policy remain outside worker-writable surfaces. Fully Autonomous still means zero Pipeliner approval gates only for compatible paths; mandatory provider and OS controls are never auto-accepted. Background service defaults off. The one-active-Issue rule, Chat-First behavior, Codex managed ChatGPT OAuth and Ollama Cloud-key-only decisions remain unchanged. This prototype adds no roadmap content to app navigation, Settings, runtime inputs or packaged assets.
