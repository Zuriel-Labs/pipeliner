Evidence and technical decisions

The current main process exposes scheduling policy fields but has no scheduler. Development already verifies provider qualification, permissions, source, live Project, Ready state, dependencies, checks, assignment and reservation before execution. Reuse that path; never create a second worker path. The workspace store already has protected SQLite, transactional migrations, backups and hash-checked records. Add one schedule-state table there.

Current host: macOS 27.0.1 (26A434), arm64; Xcode 27.0, first-launch check exit 0; Node 22.23.2. Node has no global Temporal. Use the native Foundation Gregorian Calendar for the current Mac’s weekly calendar calculation, with a strict local helper accepting only timestamp, named timezone, selected weekdays and time. Foundation nextDate supports the required next-time/first-occurrence matching. Validate actual spring gaps, fall repeats, half-hour transitions and timezone independence before relying on it. Calendar support on other hosts remains unqualified.

Node 22.23.2 timers do not guarantee precise callback timing; delays above 2,147,483,647 ms are coerced. Persist due timestamps, clamp timer delays, reread eligibility on callback and cancel owned timers during close. Timers deliver checks; they do not grant authority. Serialize GitHub requests and honor bounded retry policy, following GitHub’s official guidance. Reuse complete catalog/detail readback; cache only safe read responses where the existing transport can prove freshness. Never infer absence from incomplete access.

Design and ordered implementation

  1. Add interval/calendar policy fields. Preserve schema-1 documents and their exact hashes. Resolve additive safe defaults when reading old versions; only a reviewed PM edit publishes a schema-2 document. Old active runs retain their original revision, limits and authority.
  2. Add hash-checked per-repository schedule state with an owned transactional schema migration and backup. Record configuration identity, next due, last check/reason, eligibility time and an incomplete check/start marker. Startup treats incomplete starts as recovery-required when live state cannot prove they are safe.
  3. Implement strict calendar calculation and deterministic candidate selection with tests first. Calendar uses PM-selected weekdays (Sunday through Saturday), HH:MM and the saved named timezone. Skipped times run at the first valid time that day; repeated times run once. Intervals advance from the current bounded check, coalescing missed checks. A backwards wall clock cannot create extra checks.
  4. Implement a serialized host scheduler. Enabled startup/wake produces one catch-up per repository. Timer, network retry, Run Now and completion triggers coalesce while a check is pending. A failed read records a safe reason and bounded retry time; it never mutates or calls a model. Default completion waits for the next due check. Explicit immediate mode initiates one check after verified Development closeout.
  5. Reuse Development’s full preflight and reservation through a host-only start method, with unchanged-policy binding. Automatic starts additionally require enabled scheduling and the schedule trigger. Run Now is an explicit PM action. Fair host selection uses persistent eligibility time, then configured priority and Issue number. Reserved or busy repositories remain blocked; no stopped run is auto-resumed.
  6. Add a PM-only control channel and Settings/chat surface using existing tokens, buttons, forms, previews and scope labels. Show inherited/overridden values, timezone, next/last checks, catch-up and eligibility reasons. Reject stale context/proposals. Applying schedules cannot enable background operation or widen permissions.
  7. Run configured quality and local native checks; review correctness, security, recovery, accessibility and compatibility. Publish the supporting PR, verify exact candidate checks, integrate under standing intermediate-Issue authority, then read back Issue/Project/tree and remove only owned test resources. Final full-app PM acceptance remains outstanding.

Acceptance cases

  • Disabled installations do not poll GitHub or call providers. Changing a schedule affects future checks only; clearing a repository override restores global values.
  • Run Now works without terminal commands, uses the selected repository and the exact PM policy, and coalesces duplicates. A PM-triggered policy does not acquire automatic start authority from merely enabling checks.
  • No Ready work, open dependencies, open PR, incomplete metadata, active In Progress/In Review/Pending Review, local reservation, unqualified Dev, denied permissions, unavailable host capacity, offline or incomplete readback each produce a deterministic explanation and zero model calls.
  • Equal-priority candidates use Issue number; Project priority option order is authoritative. Across repositories older eligible work gets capacity first.
  • Durable incomplete start survives restart and blocks uncertain repetition. Full Development preflight repeats live checks immediately before mutation and binds the policy version.
  • Startup/wake coalesces missed checks into one. Restart and duplicate triggers do not replay an already attempted start. Default completion does not run the next Issue immediately; the explicit override does.
  • Calendar spring gap, fall repeat, leap/date rollover, half-hour daylight transition and host timezone change preserve saved timezone and one occurrence.
  • Settings has visible scope, review/apply/cancel, labeled inputs, keyboard focus, adequate contrast, 420px width and 200% zoom. Renderer cannot access timers, helper paths, credentials, stores or worker handles.

Risks and recovery

Live GitHub and local state can change between selection and activation. Fail closed on mismatched policy, source or catalog; keep the existing unique reservation and journaled effects. A crash after start dispatch may leave an active Issue without a reservation: record recovery-required and let existing Development controls reconcile it; do not retry the write blindly. Clock discontinuities may delay a check; one catch-up never converts missed events into work backlog. Global edits must invalidate previews and recalculate all inheriting repositories without changing active runs. Native helper outputs are bounded and validated; no network, credentials or repository content enters it.
