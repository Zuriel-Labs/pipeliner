# Local QA execution and baton

Read `qa` independently of `release`. Missing legacy QA is a discovery question, not a default pass. Keep the same primary Issue active during waiting and pickup; do not start another Issue or mark On Hold without PM direction.

1. Resolve the current turn and developer assignment from live evidence on the Issue. Read candidate commit/tree and all `qa.candidateIdentity` fields from their authorities. Include code/configuration/dependencies that affect QA. Shared identity excludes host-specific build/session values; record those in each turn and the corresponding release identity. Do not transfer one platform's artifact approval to another.
2. Incoming owner verifies the exact candidate locally before pickup. Run on the configured OS/architecture. An unavailable compatible host remains pending; emulation/containers are not a substitute for required native behavior. The same developer switching systems and two developers sharing one OS both need independent complete turns.
3. Inspect prerequisites and setup; establish test account, fixtures, dependencies, local ports, browser/native launch steps and health/readiness. Run every environment suite command in order, including build, launch, behavior and security gates required by the target. Also run repository-wide `quality.commands`; do not treat a successful lightweight Actions check as the local suite. Record each command, exit status and durable log reference on the Issue or PR, avoiding secrets.
4. Use a fresh task workspace and resource inventory before setup. `createTestWorkspace(parent)`/`removeTestWorkspace(workspace)` provide a marker-checked temporary file boundary; call cleanup in `finally` even when setup or suite fails. Keep its private ownership token local. External processes/containers/images/volumes require exact IDs, run label/token and creation evidence before removal, then exact-ID absence readback. Verify process identity/start time before stopping it; do not kill a reused PID. Never prune globally, remove shared caches or delete untracked user files. The generic helper does not delete external resources.
5. Offer PM Testing for this exact turn: target/artifact, prerequisite setup, numbered actions and expected results, regressions, limitations and the turn's configured phrase. Record actual PM response with candidate identity. Pending approval remains pending. If PM needs a running app, record each retained resource, owner and cleanup trigger. After PM Testing, remove retained resources and verify; failed or unresolved cleanup blocks completing the turn.
6. Publish outgoing evidence before reassigning: candidate, current owner/environment, full suite results, PM state, cleanup inventory, next owner/environment and confirmation that the exact candidate is available there. Publish source/artifacts through authorized repository channels; do not discard an artifact needed by the next host. Release artifacts are durable delivery outputs, not untracked temporary test files. Cleanup retained temporary copies before completing a turn.
7. Evaluate evidence with `node scripts/evaluate-qa.mjs <profile.json> <evidence.json>`. The JSON has `candidate` and ordered `records`; each record contains `turn`, `developer`, `environment`, `candidate`, `session`, `host` (available/os/architecture), `pickedUp`, `candidateAvailable`, `suite` (command/exitCode/evidence per entry), `pm` (owner/phrase/candidate/evidence), `cleanup` (verified/evidence/resources) and, for outgoing turns, `nextCandidateAvailable`. Resource entries contain kind/id/run/owner/status/evidence. Retention adds `cleanupTrigger`. The evaluator checks supplied evidence, not authenticity; agents must read real logs, live state and PM messages before recording it.
8. Pass the baton only after the outgoing turn is complete and next candidate availability is proven; assign the incoming owner and read back Issue state, Status, metadata, assignment and one active Issue. The incoming owner verifies and acknowledges pickup. One developer/one environment omits baton bookkeeping. All turns complete permits In Review; agent code review and candidate preparation occur before PM turn approval. Release and final completion are separate. After a PM response, agents own cleanup and continuation without another start/review trigger.

Any findings return work to In Progress. Candidate changes invalidate all shared QA turns conservatively: preserve historical records, discard them from the current evaluation, retest from the first turn and obtain fresh PM approvals. Cleanup historical resources even when their evidence is stale. Waiting never releases the active slot.

After an authorized exact-tree merge, evaluate existing QA records against their original reviewed source candidate and separately prove the resulting default-branch tree and immutable artifact continuity. Do not rewrite QA records to claim they tested the new merge SHA, or compare them to a future deployment ID they never covered. Only this verified integration transition preserves source QA; an unexpected tree, dependency, artifact or configuration change requires fresh turns. Final release acceptance uses the resulting release identity.
