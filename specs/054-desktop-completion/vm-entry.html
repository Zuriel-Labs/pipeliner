Issue #54 — portable Mac VM qualification entry

Continue D-22, R-25/R-39, NFR-01–NFR-04/NFR-09/NFR-11, F-05 and T-03/T-09/T-16. The existing VM producer is qualification tooling excluded from the app. It still depends on a retired personal storage controller, fixed host paths and large arbitrary reserves. Those dependencies prevent use of the current caller-owned temporary-directory contract. The native guest boundary itself remains unqualified.

This entry supersedes the retired controller instructions in the earlier VM producer plan and the host layout in the earlier guest configuration plan. Their original measurements remain historical evidence.

Official API evidence

Apple documents VZMacOSInstaller with an explicit restore-image URL and VZVirtualMachineView forwarding keyboard and pointing events through configured guest devices. Apple's WWDC26 guest provisioning session describes first-boot account creation and optional automatic login. These contracts support the existing native approach; they do not prove constructed event delivery, all service scratch locations or a completed guest trial. Checked 13 October 2026.

Plan and trust boundaries

  1. Require the same canonical private caller-owned TMPDIR used by source qualification. Resolve a clean committed repository candidate and verify all five consumed qualification sources. Allocate one fresh private VM root and two exclusive empty role files. Never accept a supplied VM root or reuse prior VM state.
  2. Remove the personal controller, receipt and source-pin dependencies. Preserve direct child handles, exact helper source/binary hashes, private PID/nonce startup gates, owned parent identity, explicit VZ devices, typed guest reports, input/neighbor readback and open-handle checks. The caller owns host storage preflight; this tool claims no filesystem sandbox.
  3. Replace personal host-layout parsing in guest fixture data with a canonical absolute path ending in the precise generated worker name and neighbor role. The controller still writes this data into the immutable input inventory. Guest data authorizes no host action.
  4. Use actual available storage without arbitrary reserves. Keep the 48-GiB guest disk and pinned Apple restore size/hash as workload requirements. Preserve individual operation cancellation and deadlines, exact stopped-process evidence and scoped cleanup. No host account, credential, network adapter or unrestricted host control is shared.
  5. Run meaningful missing/foreign/public/aliased temporary-root and restore-integrity checks. Compile the native disk/gate/guest-config harnesses with warnings as errors; add an actual owned hardlink refusal. Then run the full configured suite on the committed candidate before the real VM trial.

Acceptance

The source entry starts only from a clean exact candidate with explicit private output placement. Preflight failure creates no VM resources. A released native gate binds the current child PID, phase, private file identity and verified helper. The VM trial must independently show installation, actual guest app/window/action, escape refusals, cancellation and cleanup. A host-only harness or running flag is insufficient. Capture inspection and the complete guest result remain required before product capability is enabled.
