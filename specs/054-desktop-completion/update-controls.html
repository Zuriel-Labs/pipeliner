Issue #54 — update availability controls

D-24, S-14, R-43, NFR-10/NFR-12, F-08 and T-18 remain unchanged. Chat and Settings must share protected host policy and the same source reader/history. Availability does not authorize a download or installation. No production publisher or signing identity is invented.

Plan and architecture

  1. Add a manager regression with actual synthetic vault/history/signatures and an explicitly injected reader. Check manual availability, protected daily attempts across restart, a cached identical release, invalid envelopes, policy change, live source revocation, cancellation and shutdown. Claims about the reader's simulated transport remain separate from native TLS.
  2. Extend the existing manager with a trusted host catalog callback, protected history and the existing bounded reader. Validate exact catalog entries, unique IDs/names and public endpoints. Renderer requests can select a catalog name through PM policy; they cannot provide a URL, key, envelope or qualification flag. Snapshot and fence policy revision, source identity/key, channel and host/version before committing a result.
  3. Persist the attempt before dispatch. Manual Check Now may retry; automatic foreground checks are limited to once per 24 hours by durable history. A concurrent local check does not duplicate dispatch. A stop or shutdown aborts and awaits the reader before history/vault closure. Failed/stale checks preserve the retained sequence and previous authenticated release. Redact raw transport/storage errors.
  4. Use existing channel preview/apply/cancel for source selection too. Show safe source labels, actual last successful check, available version and source/storage failure states. Add explicit Cancel check. Installation remains unavailable until release bytes, native trust, idle effects, compatible backup and recovery are implemented.
  5. Open update history after vault unlock; expose its fixed metadata category in Data. Wire foreground startup/focus checks with no background-service change. Add the exact reader/history/manifest runtime inputs to the fixed package allowlist; keep roadmap, tests and developer launchers excluded.
  6. Run focused manager/reader/history/manifest, inventory, package and control regressions, unchanged npm run check, then native update-control qualification on the current candidate. The managed storage repair must admit execution first.

Native verification plan

Extend the existing delivery qualification with one bounded native-window check. Create an isolated protected policy/history fixture under the admitted external app run; use the app's opened vault and an ephemeral synthetic publisher. Temporarily route only the update IPC handler through the existing strict control channel to that fixture. Drive source preview/apply with native keyboard input, inspect signed availability, cancel an explicitly simulated held reader, revoke the source, and verify labels, focus, 44-pixel controls and 200% narrow-window reflow. The simulated reader does not establish public TLS or publisher qualification. In a finally path, await fixture cancellation/closure, close its stores, restore the original strict handler and renderer, and remove only the exact unchanged owned fixture. Retain numeric results in the existing run; preserve its existing bounded captures. This is test-only code excluded from packaged assets; production source and authorization controls remain unchanged.

Acceptance

A PM can select a known trusted source, switch Stable/Beta/Alpha, inspect a verified availability result and cancel a check through chat or Settings. Unknown or revoked sources never dispatch. Source/channel/policy changes deny an outstanding result. A forged reader result cannot bypass signature verification in history. Restart and failed attempts cannot erase the highest source/channel sequence or the automatic-check limit. Foreground-only polling never downloads an asset, installs, restarts, enables service or expands permissions. Shutdown waits for cancellation and preserves protected history.

Non-goals, risks and commands

This increment does not configure a production feed, generate publisher credentials, install an update, migrate or roll back app data, or uninstall anything. Existing production source absence remains visible; an injected catalog in a regression is not live publisher evidence. Policy/source changes cancel on host synchronization and are checked again before persistence. Expired cached metadata loses availability while its sequence remains. Source/catalog errors and locked/corrupt history fail closed.

Source-review correction and current evidence

Source review found that the default UTF-8 decoder strips a leading byte order mark. That could admit noncanonical bytes and then make the retained string unreadable by the history reader's JSON parser. The shared manifest decoder now retains the mark so parsing refuses it. This is a source-level finding, not an observed test result. Manifest, transport and history regressions include that case; all remain unexecuted. Node 22.23.2 TextDecoder options documents this behavior.

Host startup, focus, suspend, window closure and shutdown are wired to the manager.
