Observed incompatibilities

The current restore script creates a random directory and a replacement restore inode; the VM helper creates Disk.img with O_CREAT/O_EXCL. The reviewed proposed storage protocol instead creates one fixed private tmp/pipeliner-54-macos-worker root and both empty role inodes. It pins a controller separately from its sequential install, boot-bridge and cancellation native children. Existing early restore deletion and recursive final root deletion violate its evidence-preserving role lifecycle. Guest metadata currently admits only the old six-character root suffix and rejects the fixed leased root.

Ordered implementation

  1. First adapt the native disk writer to open only the already-created empty Disk.img through its owned directory descriptor. Require exact current UID, private directory, regular single-link mode-0600 file, zero length and unchanged path/descriptor identity. Never create, replace or truncate an unknown file. Size that same descriptor only after validation. Extend the guest metadata parser to the fixed leased root while retaining its precisely bounded previous external layout.
  2. Before a real VM run, replace the split producer launch with one actual source-pinned controller. Validate the current route/receipt/source/tree/volume, request vm-prepare and controller bind, write restore bytes in place with exact size/hash and bounded HTTPS transfer, then compile/sign the existing native helpers under that root. Keep all outputs and caches external.
  3. Gate each direct native child before any VZ work. Bind its actual executable/hash/PID/UID/start/SID/PGID and await the matching post-operation ACK before release. Stop, wait/reap and report every child phase honestly; verify the exact handles and guest result before closure. Prepare the closed input/32-byte neighbor seed before the two exact typed aliases. Verify returned-link O_NOFOLLOW, unchanged seed/input and actual guest/native window/action/escape evidence.
  4. After all three passed phases, release the verified boundary, complete the exact trial, then release named disposable roles. Failure remains failure: settle all children, abort, release only the observed incomplete boundary and exact roles. Preserve receipts, small fixtures and original cause. Remove no retained evidence; cleanup follows exact task ownership and existing authority.
  5. Resolve the proposed helper's two native qualification gaps and review any separately sealed correction before activating this producer. Do not run the old VM script through the new route or use a generic alias exception.

Acceptance and verification

The focused native filesystem harness must accept an empty owned private role, preserve its inode while writing a tiny synthetic body, and deny missing, nonempty, aliased and permissive roles without changing their bytes. Test the single-link predicate with explicitly injected metadata; do not create a hardlink that the outer scanner correctly refuses. Actual hardlink native admission remains unqualified. The actual normal helper must compile with ARC and warnings as errors. The guest configuration harness must admit both exact declared layouts and retain all hostile-input negatives. Compile and run those bounded checks through the installed managed launcher, with binaries and fixtures under the external run; remove only unchanged owned disposable resources in finally. Then run the configured complete quality command and the separately admitted actual VM trial. Record exact source/tree/helper/tool versions, receipts, phases, measurements, limitations and cleanup.

Risks and non-goals

Native stop flags and phase outcomes are producer attestations; actual process absence/handle evidence and guest/window observations remain necessary. VM/download/soak and production broker are not run in this first increment. No private credential sharing, networking device, global input event, host fallback, broad cleanup, source migration or OS/provider consent bypass is added. The proposed VM helper still has unqualified native undersized-completion and partial-release cases. The complete quality command currently stops before TAP results with a separate pre-STOP watchdog protocol refusal; do not claim a suite pass.
