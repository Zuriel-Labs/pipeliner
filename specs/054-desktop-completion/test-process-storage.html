Issue #54 — test process admission

This developer-only increment enables the configured complete quality command and explicit native qualification under the reviewed external test-storage contract. It changes no product requirement or PM authority. Final Draft 1.0 and the existing Issue acceptance criteria remain the baseline.

Evidence and cause

The strict scanner previously encountered deleted entries while fixture teardown was running. Candidate 9a1a595dd66417b9 supplies authenticated frozen audits of the producer session and explicitly enrolled detached sessions. The source delta and 52 preserved/current file hashes plus two selected receipt hashes are verified. This helper requires the project producer to wait for its ready boundary, hold each new detached child before it writes or exits, serialize enrollment and release the child only after the matching post-audit acknowledgment. Existing production Git and worker-shell calls deliberately use detached groups for cancellation; removing that isolation is unacceptable.

Implementation plan

  1. Add one explicit developer process adapter and one managed quality producer. Reuse the installed versioned wrapper, existing context validation, Node child-process objects and native exec. Keep all test code outside package inputs.
  2. At explicit activation, verify the current running Issue #54 receipt, source pins, owned external paths and original Chromium record where applicable. Wait for the initial enrollment boundary. Create a private source-pinned preload in this run only.
  3. Intercept the actual ChildProcess spawn boundary so both spawn and promisified execFile retain their original object, streams and child PID. Gate detached launches with a bounded Python exec helper; serialize through one run-owned directory lock. Verify exact enrollment acknowledgment before releasing the gate. Preserve detached:true and the original target environment, working directory and arguments.
  4. Preload only the exact host Node executable into nested host fixture processes, including explicitly cleared environments and synchronous execFile calls. Do not add provider credentials, worker permissions or runtime tools. Explicit native source qualification activates the same adapter before importing its host modules; packaged startup remains denied.
  5. Run three bounded native probes before the full configured npm run check: detached spawn with output/nonzero exit, promisified execFile with its child PID, and a nested Node fixture with a cleared environment. Preserve complete scanner refusals and process closure. Then qualify actual Recovery and the protected 25-workspace cached-navigation workload.

Acceptance and verification

Each gated target starts only after verified enrollment; the resulting PID/group and original output/exit semantics remain correct. All groups and target processes close. Missing, changed, stale, mis-scoped or incomplete receipts/pins fail closed. The original scanner, budget, native ownership and watchdog checks remain intact. The full suite uses the unchanged configured command; no test is skipped or assertion relaxed. Record source/tree, exact route/helper hashes, acknowledgment/group counts, result, elapsed time, process closure and retained external evidence. Native behavior and Human acceptance remain separate gates.

Commands: reviewed explicit-group launcher with --producer scripts/desktop-quality.mjs --producer-sha256 <actual SHA-256>, followed by node scripts/desktop-quality.mjs --probe or node scripts/desktop-quality.mjs; native qualification uses the same reviewed Chromium route and actual desktop-app producer hash. Syntax checks and git diff --check precede execution. All generated gates, preloads, logs and caches stay in the authenticated external run.

Risks and non-goals

Node's low-level spawn boundary is implementation-sensitive: verify the actual installed Node version and official Node 22 child-process API, including promisified child objects. Blocking admission adds instrumentation overhead and must not be reported as product latency. Concurrent test processes need serialized enrollment; uncertain stale locks refuse rather than guessing ownership. The adapter does not prove worker isolation, provider integrations, OS service scratch routing, VM admission or cross-platform behavior. No global activation, scanner relaxation, broad kill/prune, dependency installation, PM gate or product configuration is added.
