Risks and non-goals

Node's low-level spawn boundary is implementation-sensitive: verify the actual installed Node version and official Node 22 child-process API, including promisified child objects. Blocking admission adds instrumentation overhead and must not be reported as product latency. Concurrent test processes need serialized enrollment; uncertain stale locks refuse rather than guessing ownership. The adapter does not prove worker isolation, provider integrations, OS service scratch routing, VM admission or cross-platform behavior. No global activation, scanner relaxation, broad kill/prune, dependency installation, PM gate or product configuration is added.

Local Git cancellation finding

The native probe exposes an existing product error: Node 22.23.2's execFile implementation omits detached when calling spawn. Promisified execFile retains its documented child object but inherits the producer group; a passed detached property never creates a cancellation group. The three adapter probes must preserve this behavior and verify two actual detached enrollments. Correct local inspection to use the supported spawn API with the same restricted environment, bounded stdout/stderr, per-command timeout, overall abort signal and verified group teardown. Reuse the repository's existing spawn/close/group cleanup pattern. Before implementation, add a regression that detects the missing detached constructor option on the actual Git path. Retain working modifications, remote denial and actual cancellation tests; native repository qualification remains required.

Host fixture temporary input routing

The serialized worker helper uses a literal /tmp input path. Its production container has that private tmpfs, but host helper tests must route their synthetic input externally. Use Node's standard temporary directory resolution; pass the managed temporary directory explicitly in the host fixture's otherwise restricted environment, assert that the observed input file belongs there, and retain its deletion check. The container's default /tmp path and permissions stay intact. Do not run the known internal-writing form merely to obtain a Red result.

Workload fixture cleanup correction

The new 25-workspace qualifier created 23 additional directories, but the existing launcher correctly requires an empty owned fixture root before removing it. Record each created directory identity immediately, and remove only that unchanged, owned, canonical, private empty directory in the qualifier's outer finally path. Keep protected fixture records until the entire test app root is removed. No production workspace-removal API is needed.
