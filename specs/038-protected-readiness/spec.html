Risks and recovery

  • GitHub access can be partial/revoked or owner-specific: require complete current reads and the scoped App; use the separate existing setup grant only for personal Project operations. No broad-token fallback.
  • Remote values can change between preview/write/clone/readback: bind exact identities and read before each effect plus final full readback; wrong status/options or two active cards block mutations. External provider controls are never bypassed.
  • Creation may succeed before a reply is lost: keep dispatched/uncertain intent, refuse automatic replay and allow only deliberate matching-result readback/selection. Preserve resources, unrelated labels and original context.
  • Workspace changes may race an in-flight request: abort the old host lease, check host-owned context and policy before every next effect, save the outcome to its original repository, ignore old UI responses.
  • Ready is a GitHub label, so external authorized users can edit it: surface observed drift; no false exclusive-authority claim. An active removal request is rejected locally even when GitHub would allow it.
  • Large/unknown Project contents and paginated Issue/dependency results: bounded complete reads, stable/unique identity checks and explicit partial-access failure. Full scale/soak and native assistive technology remain later evidence.

Review corrections and evidence boundaries

Tracked cards without a classified Status block mutations; a newly created Issue is the sole bounded exception while its own metadata is being filled. A PM policy change stops the next write, preserves the known created Issue and requires a fresh preview of remaining changes. Known lost creation, Project-link or field replies can reconcile their exact result; an unknown creation reply never authorizes a duplicate. Review found that a lost Project-link reply blocked readback before its own Status was set. The failing restart regression now passes: only the journal's verified creation identity receives the existing bounded metadata exception during repair, and the Project link is not repeated. Secret-like agent drafts are rejected before persistence. Non-closing PR references are read from typed timeline events alongside current linked PRs; referenced history is labelled separately, with its own repository and current check head. The live GitHub schema and the read-only Issue #36 reference/check query were inspected with GitHub CLI; that does not prove the Desktop App's authenticated grant.

GitHub provides no transaction spanning Project Status and label endpoints. The host reads before and after a narrow Ready update and rejects active removal, but cannot claim an atomic lock against an external authorized GitHub edit racing the request. Untracked or unclassified external Issues and changed Project mappings remain blocked until their tracking/mapping is resolved; no automatic Backlog assignment or Ready repair is invented. This is qualification evidence for bounded intake, not a claim that the complete Desktop is ready for PM Testing.
