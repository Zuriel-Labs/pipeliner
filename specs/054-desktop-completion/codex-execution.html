Acceptance criteria

  • A qualified managed Codex model can supply a typed Development request to the existing broker. No shell, repository effect, policy change or credential export occurs in AppServer.
  • Every returned request matches the exact native thread, turn and declared tool; malformed, foreign, oversized or interaction-required output refuses. The native turn is terminal and its process group is reaped before the engine receives requests.
  • Model/account changes and stale bridge evidence revoke eligibility. Refresh preserves only current applicable qualification. Abort, disconnect and shutdown fence late results and await owned cleanup.
  • The existing native marker probe, Ollama path, engine authority checks, renderer restrictions and framework adopters retain their behavior. No unsupported path is advertised as Fully Autonomous.
  • Tests and native evidence report their actual scope. Human acceptance, other hosts, isolated guest installation, notarization and the remaining complete-app journeys are separate pending gates.

Non-goals, risks and commands

No SDK dependency, general tool executor, provider-home worker, new model default, auth route, automatic approval, background operation or roadmap runtime input is added. The bridge reconstructs the host's verified conversation for each ephemeral native turn; it does not claim persistent provider-thread continuity for Development. Interruption must settle pending requests; native evidence must confirm that contract. The pinned API has no verified native output-token ceiling for maxOutput. That input is validated but is not advertised as a provider-enforced token cap. Usage remains unknown and the existing engine refuses configured hard token/cost limits. Input and normalized output use the canonical JSON limits (524,288 characters, 50,000 nodes and depth 32), with an additional 1 MiB byte check; AppServer wire traffic is limited to 2 MiB and 4,096 events. These are host bounds, not provider token or billing guarantees. Request/stream growth remains bounded and raw provider errors stay private.
