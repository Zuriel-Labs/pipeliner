Ollama Cloud agent loop: partial qualification

Current Mac evidence, with the live inference gate left open.

Decision

The configured local credential did not authenticate direct Cloud inference. A minimal POST https://ollama.com/api/chat returned HTTP 401 for gemma4:31b, including without tools. A deliberately invalid credential received the same status. The synthetic streamed tool loop, resumed answer, usage counters and model capability are therefore not qualified live. No alternate credential or provider session was used.

The Cloud catalog returned HTTP 200 and 17 API model names, including gemma4:31b. Catalog access does not establish inference permission. The endpoint and model naming follow the official Cloud guide; direct Cloud inference authentication follows the official authentication guide.

Risk and next verification

The probe denies tool dispatch until a complete terminal stream and exact target, nonce and policy epoch are validated. It checkpoints a single synthetic effect with restrictive mode and checks replay on resume. The untested Cloud response shape may differ from the local fixtures. A fresh locally configured Cloud API key with inference access is required for the live request, streamed tool call, resume and usage evidence. Do not paste a key into chat or GitHub; provide it through a trusted local secret path and rerun node desktop/ollama/qualify.mjs. The probe prints only bounded metadata and error categories.

Temporary checkpoint directories are removed by the probe in success and failure paths; this blocked HTTP 401 path created none. No local Ollama daemon or application process was started.
