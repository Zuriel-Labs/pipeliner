Bounded outcome and design

A local Mac application with one synthetic qualification surface, a narrow preload bridge and a bundled arm64 native helper. Evaluate Electron 44.4.5 after verifying its current official release and downloaded integrity. The qualification harness uses JavaScript and native HTML controls; TypeScript/React product construction remains the A-01 recommendation, outside this shell experiment. No framework change or production dependency decision is inferred from that simplification.

Use system type, four-pixel spacing, 16-pixel text, quiet workbench surfaces, text-labeled states, teal diagnostic activity and indigo decisions. The screen identifies itself as a local shell prototype; no chat, repositories, roadmap, Settings or product workflow appears. Controls cover bounded IPC, native dialog, helper response/failure/recovery and readable evidence. Status announces completed diagnostic actions politely without moving focus. Use real buttons, visible focus, minimum 44-pixel targets, contrast, scaling/reflow, system theme and reduced-motion/high-contrast support.

Architecture, trust and data

  • Main owns window/native menu, allowlisted local resources, validated IPC and one fixed native executable. Renderer has no Node, generic IPC, shell or filesystem exposure. Preload exposes one method per diagnostic operation.
  • Local custom secure protocol serves an exact asset allowlist; deny arbitrary paths, methods and destinations. Enable sandbox/context isolation/web security. Deny unexpected windows, navigation, webviews, permissions and renderer network. CSP disallows inline/eval scripts, frames and remote content.
  • Validate sender WebContents, main frame and exact application URL on each privileged request; validate exact payload keys/types/lengths. A compromised allowed renderer can invoke these harmless diagnostics. These checks do not authenticate a Human PM.
  • The native helper accepts only fixed ping/stop/fail lines, bounded input/output and no paths. Spawn only the packaged fixed executable with a minimal environment and no credentials. Record exit, enforce timeout and terminate only the owned child. Success, forced failure and parent termination have cleanup assertions.
  • Store synthetic timing/results and app caches in a task-specific directory. No provider requests, telemetry, secrets, existing sessions, persistent service or start-at-login registration. Keep artifact and evidence ownership explicit.

Risks and verification limits

Chromium/Node in the trusted main and unrestricted helper privileges do not prove agent isolation. Ad-hoc signatures do not prove Developer ID/Gatekeeper/notarization distribution. App screenshot and accessibility-tree APIs do not prove real screen-reader or input success. System foreground contention and warm disk caches affect timing; publish their limits. No CPU/memory ceiling has been agreed; measurements inform later decisions. Electron download scripts must stay local. Missing Computer Use tooling may limit Agent native interaction; programmatic and Human results must remain distinct.
