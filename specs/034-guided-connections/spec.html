Outcome and requirement map

A persistent, accessible Desktop connection flow available through ordinary chat and Settings. Host processes own credentials and provider clients. The PM sees destination, account, allowed resources, credential status, last verified health, and selected-model capability. No terminal or raw configuration is part of the PM task.

Evidence and settled mechanisms

  • Existing desktop/codex/qualify.mjs implements isolated stdio App Server, managed login/cancel/logout, empty environments and typed dynamic tool tests. Reuse its protocol rather than introduce externally managed ChatGPT tokens.
  • desktop/github/device.mjs already implements no-secret device flow and refresh with bounded replies, expiry and cancellation. desktop/github/access.mjs contains the qualified fixed-origin transport and final permission map; move reusable transport without changing fixture authority. Repository execution continues to use App credentials; optional setup/personal Project OAuth remains separate.
  • desktop/ollama/qualify.mjs already implements fixed-origin direct Cloud requests, strict bounded NDJSON parsing and synthetic tool-loop checks. Production connection management does not expose its temporary development relay.
  • desktop/core/storage.mjs supplies protected SQLite files; core/control.mjs supplies registered-main-frame control validation. Reuse both. Existing prototype/style.css supplies semantic navy/mint/lavender tokens and accessible control states.
  • Current official documentation supports managed Codex account/login/start/read/cancel/logout and provider-owned refresh. Electron 44.4.5 installed types expose async safeStorage. Protect a random AES-GCM key through that OS service; authenticated encryption protects the connection record, including its embedded generation. Reject unavailable storage and Linux basic_text; this Mac qualification does not imply Windows/Linux isolation.

Design brief and task paths

Keep the established three-stroke Pipeliner mark, system typography, restrained navy surfaces, mint action/evidence accents and lavender PM intent. Chat occupies the primary surface; an inspectable Connections Settings view shares the same actions. Installation scope is visible. No engineering roadmap, Issue identifiers or qualification controls appear in product navigation.

  1. Fresh install: explain the three destinations and provide suggested connection requests. “Connect GitHub”, “Connect Codex” or “Connect Ollama” opens the appropriate protected flow. An ambiguous request asks the PM to choose a destination without any authorization attempt.
  2. GitHub: show the scoped App's account/permission explanation, native device code and fixed GitHub authorization destination. The optional setup/Projects connection is explicitly distinct, including broader repo/project consent and limited host operations. Full pages and identities must validate before resources are offered.
  3. Codex: show provider-managed ChatGPT login, launch only the validated provider URL, and provide a local Cancel control while waiting. After successful notification, read account and catalog; neither alone proves inference/tools.
  4. Ollama: show direct Cloud destination and native secure key entry. The ordinary renderer never receives its value. A cancelled field preserves the previous connection; replacement fences prior work and verifies new state.
  5. Test a selected model: state that a short synthetic prompt/tool result is sent to the selected provider and may consume usage. No repository material is sent. A successful bounded tool loop records its tested model and time; unavailable usage remains unavailable. No automatic test on connection or restart.
  6. Disconnect: immediately invalidate connection generation and cancel affected requests. Remove local secret records; verify Codex-managed logout. Explain any incomplete cleanup and that remote GitHub/Ollama authorizations may still require provider revocation. Subsequent effects require a fresh live connection preflight.
  7. Close: cancel connection/test work and close owned helper/App Server processes. Background remains off. Reopening restores encrypted state and revalidates account/catalog on deliberate refresh; interrupted actions never replay.

Reachable states: disconnected/empty, secure storage unavailable, connecting/waiting for provider, checking, connected with unverified capability, tested, limited access, expired/reauthentication required, offline/failed, cancelled, local disconnection with provider cleanup pending. Text explains next action independently of color. Keep Cancel/Disconnect available during provider outage. Return focus to originating chat or control; preserve typed input. Semantic 44px controls, keyboard activation, visible focus, live result announcements, light/dark, 420px narrow view, zoom, high contrast and reduced motion apply. Screen-reader/Human observations must be recorded separately.

Implementation plan and ordered tasks

  1. Write failing focused checks for encrypted records, swap/corruption, generation fencing, late auth/refresh, revoked access, bounded complete resource discovery, secret rejection and PM-origin IPC.
  2. Implement a private SQLite connection vault using existing protectedFile and Node AES-256-GCM; wrap only its random key with async OS protected encryption. Keep plain credential records and cipher handles in host memory only. Atomic generation changes prevent stale asynchronous replies from restoring a disconnected connection.
  3. Reuse/harden qualified provider transports. Add a host connection manager with typed connect/cancel/refresh/test/disconnect operations, safe error categories and minimal public view. No renderer-supplied URL, token, arbitrary RPC, authenticated request or shell command.
  4. Implement a small AppKit NSSecureTextField helper with bounded pipe output, Cancel and confirmed submit. Compile locally; launch without credentials in argv/env. Close/remove only owned test helpers. Packaging/signature identity is D-23/D-24 work.
  5. Add the Desktop app entry, locked protocol/preload, shared-token chat and Connections Settings. Same registered-renderer command path serves both. Secret-like chat input is rejected before history or transport; no general model call is needed for first-run guidance.
  6. Run focused and configured quality checks; qualify actual safeStorage, native secure field, own-window keyboard, restricted renderer, restart/corruption and cleanup. Run available live unauthenticated/provider read-only evidence without borrowing existing credentials. Remediate and review source, UI and security.
  7. Publish exact source/tree PR with full Showcase, results and pending evidence. Apply standing intermediate-integration authority, verify exact-tree main/checks, close the sole Issue and clean task resources. Continue to D-11; final Human acceptance is not claimed.

Acceptance checks

  1. One connection action has equivalent chat and Settings results; unknown/ambiguous/quoted instructions have no effect. Foreign frames, extra fields, stale context/generation and unsupported operations are denied.
  2. Raw secrets are absent from renderer state, ordinary chat, logs, database bytes, exported public view, helper argv/env and synthetic test prompts. Decrypting a swapped, truncated, modified or wrong-generation record fails closed.
  3. Refresh/cancel/disconnect races cannot repersist an old credential or restore old access. Missing, revoked, expired or partial resource evidence does not become an authorized repository/Project. All pagination is bounded and complete.
  4. Provider-managed Codex login stays isolated; no auth.json or copied session. Native Ollama field masks input. Unavailable secure storage blocks new credential entry/use; no plaintext fallback.
  5. Account/catalog health and actual selected-model test evidence remain separate. Errors show actionable reauthentication, retry, cancel or disconnect. No provider fallback, repository setup or hidden approval occurs.
  6. Closing the last app window cancels owned operations and leaves no owned helper/process. Background is off. Restart restores only verified local records and never resumes a mutation or inference automatically.
  7. Full repository checks and relevant actual Mac checks pass; exact versions/timing and ownership/cleanup are recorded. Synthetic/live/native/Human evidence are correctly labeled.
