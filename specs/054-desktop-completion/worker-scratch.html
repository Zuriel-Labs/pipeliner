Issue #54 — owned worker tool scratch

Focused prerequisite for D-22/D-27, R-25, NFR-09/NFR-11/NFR-14/NFR-16, F-10 and T-03/T-09/T-14. Keep the existing restricted Linux worker architecture, PM limits and one active Issue/Dev per repository. The separate unqualified Mac guest installer is not evidence for this Linux runtime.

Observed flow and primary evidence

openWorkerEnvironment validates a private app-owned directory, private tool home and private Lima state. Its fixed host command environment passes HOME and LIMA_HOME but no TMPDIR. The inherited caller environment is deliberately excluded. Lima's shell implementation uses Go temporary directories for supported host operations; Go's TempDir contract uses TMPDIR on Unix. Lima's internal directory documentation places macOS caches under the tool's home. Installed Lima resolves to version 2.2.1. These contracts support routing cooperating host-tool scratch into the existing owned scope. They do not establish every native service's behavior.

Smallest implementation and ordered plan

  1. Add a failing assertion on the actual source-executed host command environment in the existing private-files inspection fixture. Keep cold inspection read-only, including legacy state that has no additional temporary directory.
  2. Set TMPDIR to the already verified app-owned environment directory. Reuse its ownership checks and existing private tool home; add no new profile setting, directory migration, inherited credentials or guest permission. Preserve fixed executable/arguments, detached child tracking, cancellation, VM/image/configuration identity and cleanup.
  3. Run the affected source checks and all configured quality commands on a clean committed candidate. Before actual Linux provisioning, inspect the installed helper chain, cache/temp outputs, pinned guest image, container definition, explicit output locations and current native prerequisites. Qualify the real worker lifecycle and five-run workload separately.

Acceptance

Every trusted Lima command receives an absolute TMPDIR equal to the verified private environment scope. Cold inventory creates no new files or execution controls. A missing, aliased, foreign or permissive environment still refuses; marker/configuration drift and cancellation still refuse. Existing HOME isolation, LIMA_HOME, no host mounts, no forwarded keys/agent, restricted container and exact ownership checks remain intact. There is no change to ordinary application credentials or the caller's environment.

Checks and risks

node --test desktop/core/worker.test.mjs; npm run check; then the actual owned Linux worker lifecycle under its existing API. Risks include native scratch that ignores tool environment, socket-path length, long-lived host-agent resources, image download/provisioning failure and five-worker memory contention. Stop the affected producer when output containment or ownership is unverified. Measure the actual reference host; do not reduce or claim the agreed workload from unit checks.

Non-goals

No new worker transport, image/version change, VM memory change, production host-automation authority, provider integration, personal storage policy in shared code, completed five-run qualification or 24-hour soak claim. Do not use this TMPDIR setting as an OS sandbox assertion or change unrelated tools/apps.
