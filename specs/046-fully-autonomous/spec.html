Baseline: Final Draft 1.0, D-16; dependency Issue #44 / D-15. Source inspected: e9504c8bb5c2b838bd83cab2a808582fcce91297. Existing presets publish PM-owned versioned graphs, but execution ends at a candidate and requires approved QA for integration. This specification connects the ungated graph to the existing durable integration path.

Focused design

Reuse the existing pipeline, SQLite ledger, host manager, required-check verifier, remote-effect journal and worker supervisor. Add one shared integration-authority validation function. A captured graph with any PM QA requires its current approved Showcase; a captured graph with zero QA uses its policy revision/hash and pipeline hash. Both require the current terminal integration step and unchanged candidate tree. Authority identity becomes part of the merge preconditions. Ungated runs never offer a Showcase approval, but retain review/check evidence and disclose their candidate and progress.

Live repository integration exposed an additional capability requirement: Pipeliner allows squash only (allow_merge_commit=false, allow_squash_merge=true, allow_rebase_merge=false). GitHub rejected the attempted merge-commit operation without changing the PR. Before worker preparation, select an actually allowed merge or squash method and capture it in the run ledger. Recheck that exact method before a new merge dispatch. Missing flags, changed repository identity or a rebase-only path block before execution; no repository control is edited. Existing one-parent squash lineage verification is reused. Legacy captures default to their previous merge method. Already-applied effects still reconcile without another write.

Framework compatibility follows the baseline's explicit versioned Desktop-profile contract. Legacy validators and source profiles continue to require PM Testing. PM selection of an autonomous preset or explicit custom graph publishes the Desktop policy; the preview discloses that Desktop gates now govern new runs while legacy files and other framework agents retain their behavior. Each new run captures {kind:"pipeliner-desktop",version:1} inside the hash-protected ledger, alongside the PM policy/pipeline identities. Legacy ungated records without this migration descriptor cannot integrate. No new global setting or source-file mutation is needed.

Before activation or worker preparation, reject unsupported delivery/post-integration routes, missing declared permissions, hard metrics unsupported by this execution adapter, missing explicit Desktop workflow selection or provider capability. Acquire/check/close the provider lease before execution. Ungated execution additionally requires the qualified prompt-free adapter and an exact source branch readback with protected=false. Protected integration paths remain explicitly unqualified; no review, merge queue or provider/OS control is disabled. Branch controls and required checks are rechecked at merge, which still uses expected head SHA and never bypasses GitHub controls.

After publication, the worker pauses and the host either presents the captured PM gate or saves exact closeout context and proceeds to integration. Resume at an ungated integration boundary invokes reconciliation/closeout directly, preserving counters and avoiding repeated model or publication requests. Existing supervised approval recovery remains unchanged.

Pending GitHub checks and asynchronous mergeability are observed automatically with bounded, cancelable waits inside the original captured deadline. No model requests or approval inputs occur while waiting. Failures, ambiguous identities, protection and drift block immediately; missing evidence never becomes a pass.

Non-goals

No scheduler, background service, Dev takeover, expanded usage accounting, new dependency, extension protocol, native installer delivery, other-host qualification or final application acceptance. Product Ollama uses direct Cloud API keys; the explicitly authorized installed Cloud relay is development qualification only. No credential/session copying or protected-path bypass.

Risks and limits

  • GitHub has an expected-head merge precondition but no expected-base merge precondition. Fresh base/control checks and exact post-merge tree/lineage verification remain mandatory; a race blocks completion.
  • Protected branches remain incompatible with this bounded ungated adapter. Block before worker execution and explain the exact requirement. Legacy profile validation and mandatory PM Testing remain unchanged outside explicitly selected Desktop execution.
  • Hard token/cost budgets remain unsupported for this adapter and block before activation. Existing turn/time bounds remain captured; D-17 owns fuller accounting/takeover.
  • Lost replies, revocation and cleanup failure must retain the claim and evidence. No automatic next Issue.
  • Actual development relay or administrative GitHub transport evidence does not establish product App authorization, direct Cloud credentials, Human QA or other platforms.
